# Asynchronous FIFO Design


## Overview

This project implements a parameterized Asynchronous FIFO for reliable data transfer between two independent clock domains.

Asynchronous FIFO is commonly used in multi-clock digital systems for safe Clock Domain Crossing (CDC). Since the write clock and read clock are asynchronous to each other, direct transfer of control signals can lead to metastability.

This design uses:

- Gray code pointer synchronization
- Two flip-flop synchronizers
- Separate read and write clock domains
- Independent full and empty flag generation


The architecture is based on the FIFO design methodology proposed by Clifford E. Cummings.

---

# Features

- Dual clock asynchronous FIFO
- Independent read and write clock operation
- Parameterized FIFO depth and data width
- Gray code based pointer synchronization
- 2-FF synchronizer for CDC
- Full condition detection
- Empty condition detection
- Safe data transfer between asynchronous clock domains


---

# FIFO Architecture

The asynchronous FIFO consists of two independent clock domains:

## Write Clock Domain

The write side performs:

- Write pointer generation
- Binary to Gray code conversion
- Memory write operation
- Full condition detection


## Read Clock Domain

The read side performs:

- Read pointer generation
- Binary to Gray code conversion
- Memory read operation
- Empty condition detection


The Gray coded write pointer is synchronized into the read clock domain, and the Gray coded read pointer is synchronized into the write clock domain using two flip-flop synchronizers.

# RTL Design Modules

The design is divided into multiple RTL blocks. Each module performs a specific function required for asynchronous FIFO operation.


---

## 1. FIFO Top Module (`fifo_top.v`)

The `fifo_top` module is the top-level integration module of the asynchronous FIFO.

It connects:

- FIFO memory
- Write pointer logic
- Read pointer logic
- Write-to-read synchronizer
- Read-to-write synchronizer


The module contains two clock domains:

- Write clock (`wclk`)
- Read clock (`rclk`)


It provides the complete FIFO interface:

| Signal | Description |
|---|---|
| wdata | Input data for write operation |
| rdata | Output data from FIFO |
| winc | Write enable |
| rinc | Read enable |
| wfull | FIFO full indication |
| rempty | FIFO empty indication |


![FIFO Top Schematic](DOCUMENTATION/Fifo_Schematic.png)


---

# 2. FIFO Memory (`fifomem.v`)

The FIFO memory module stores the data written into the FIFO.

The memory depth is calculated as:

```
DEPTH = 2^ADDRSIZE
```


Write operation occurs only when:

```
wclken = 1
and
wfull = 0
```


The read data is continuously available based on the read address generated by the read pointer.


Functions:

- Store write data
- Provide read data
- Prevent writing when FIFO is full


![FIFO Memory](DOCUMENTATION/fifo_mem.png)



---

# 3. Write Pointer and Full Logic (`wptr_full.v`)

This module controls the write side operation.

Functions:

- Generate binary write pointer
- Convert binary pointer to Gray code
- Generate memory write address
- Generate FIFO full flag


The binary pointer is used for memory addressing, while the Gray coded pointer is transferred between clock domains.


The write pointer increments only when:

```
winc = 1
and
FIFO is not full
```


The FIFO full condition occurs when the next write pointer reaches the synchronized read pointer position.


![Write Pointer Full Logic](DOCUMENTATION/wptr_full.png)



---

# 4. Read Pointer and Empty Logic (`rptr_empty.v`)

This module controls the read side operation.

Functions:

- Generate binary read pointer
- Convert binary pointer to Gray code
- Generate memory read address
- Generate FIFO empty flag


The read pointer increments only when:

```
rinc = 1
and
FIFO is not empty
```


The FIFO empty condition occurs when the next read pointer becomes equal to the synchronized write pointer.


![Read Pointer Empty Logic](DOCUMENTATION/rptr_empty.png)



---

# 5. Write-to-Read Synchronizer (`sync_w2r.v`)

This module transfers the Gray coded write pointer from the write clock domain to the read clock domain.


Since both clocks are asynchronous, directly sampling the pointer may cause metastability.

A two flip-flop synchronizer is used to safely transfer the pointer.


Operation:

```
Write Domain
      |
      FF1
      |
      FF2
      |
Read Domain
```


The synchronized write pointer is used for empty flag generation.


![Write to Read Synchronizer](DOCUMENTATION/w2r_sync.png)



---

# 6. Read-to-Write Synchronizer (`sync_r2w.v`)

This module transfers the Gray coded read pointer from the read clock domain to the write clock domain.


A two flip-flop synchronizer is used to reduce metastability probability.


Operation:

```
Read Domain
      |
      FF1
      |
      FF2
      |
Write Domain
```


The synchronized read pointer is used for full flag generation.


![Read to Write Synchronizer](DOCUMENTATION/r2w_sync.png)



---

# 7. Two Flip-Flop Synchronizer (`two_ff_sync.v`)

The two flip-flop synchronizer is a standard CDC circuit.

The first flip-flop samples the asynchronous signal and may enter metastability.

The second flip-flop provides a stable synchronized output for the receiving clock domain.


This technique reduces the probability of metastability propagation.
